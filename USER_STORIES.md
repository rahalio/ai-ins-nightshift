# Nightshift — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### Valuation actuary

- As a valuation actuary, I want the close to run overnight to completion without me monitoring it, so that my working day starts with results rather than with job restarts.
- As a valuation actuary, I want reserve and earnings movements already attributed to named causes when I arrive, so that my first task is judging the movement rather than discovering it.
- As a valuation actuary, I want to drill from a reported figure to the model version, assumption version, and extract that produced it, so that I can defend the number without reconstructing the chain.
- As a valuation actuary, I want reconciliation breaks to block sign-off, so that I am never asked to certify a figure that does not tie.
- As a valuation actuary, I want a drafted narrative I can edit and sign, so that I stop rewriting last quarter's report from scratch.

### Chief Actuary

- As the Chief Actuary, I want results and narratives available before the working day starts, so that I can brief the executive on the same morning the close completes.
- As the Chief Actuary, I want to ask why a product's result moved and get the attributed answer with the underlying variance analysis, so that I move from explaining what happened to advising on what to do.
- As the Chief Actuary, I want a live view of regulatory deliverables against their statutory deadlines, so that the memo cycle stops consuming half a year of function capacity unplanned.
- As the Chief Actuary, I want the split of cycle time between production and analysis reported each period, so that I can evidence the function's shift towards insight to my executive and my board.

### Model owner and actuarial systems team

- As a model owner, I want the run graph derived from observed dependencies, so that undeclared dependencies stop causing overnight failures.
- As a model owner, I want a model change to require quantified impact before it enters a reported close, so that my change is never mistaken for experience variance.
- As an actuarial systems lead, I want failed jobs retried where safe and escalated to a named owner where not, so that the on-call burden is bounded and explicit.
- As a model owner, I want documentation maintained as a condition of production status, so that knowledge survives the four-and-a-half-year average tenure the profession now assumes.

### Assumption owner and pricing actuary

- As an assumption owner, I want assumption changes versioned with their supporting experience study and their quantified impact, so that the basis for a change is inspectable years later.
- As a pricing actuary, I want the pricing basis for a filing reconciled against the valuation basis for the same cohort, so that a filing does not create an inconsistency I have to explain at examination.
- As a pricing actuary, I want to query in-force concentrations such as extreme-age and rider exposure directly, so that a pricing question does not become a data project.

### Actuarial control, audit, and external reviewer

- As an actuarial control reviewer, I want the change log, reconciliation results, and attestation record for a close available as a package, so that control testing does not require interviewing the team that performed the work.
- As an internal auditor, I want access to pre-announcement results and assumption changes restricted and logged by role, so that information-handling controls are demonstrable.
- As an external reviewing actuary, I want documentation sufficient to assess the work without the original author present, so that my review meets professional standards.
- As an actuarial control reviewer, I want the system to refuse to publish an actuarial opinion generated without a named actuary's attestation, so that automation cannot erode the function's independence.
